지정한 plan 문서를 기반으로 브랜치 생성 → 구현 → 테스트 → REST Docs → PR 생성까지 자동 수행해줘.

plan 문서 경로: $ARGUMENTS

## 1단계: plan 문서 읽기
1. 지정된 plan 문서를 Read로 읽어 구현 내용을 파악
2. plan 문서에서 기능명(feature name)을 추출

## 2단계: 브랜치 생성
1. 현재 브랜치에서 새 브랜치를 생성
2. 브랜치명 규칙: `backend/feat/{feature-name}` (plan 문서의 기능명을 kebab-case로)
3. git checkout -b {브랜치명}

## 3단계: 구현
/implement 커맨드를 사용하여 plan 문서의 내용을 구현한다.
plan 문서의 구현 순서를 따를 것.

## 4단계: 테스트 작성
/kotest 커맨드를 사용하여 구현한 코드의 테스트를 작성한다.
테스트 대상: 새로 생성/변경된 도메인 객체, 서비스, Value Object, 포트 구현체.
전체 테스트 실행하여 통과 확인 (./gradlew test).

## 5단계: REST Docs 작성 (API가 포함된 경우만)
새로운 API 엔드포인트가 생성/변경된 경우에만 /rest-docs 커맨드를 사용하여 REST Docs 테스트를 생성한다.
API가 없는 기능(배치, 도메인 로직만 변경 등)이면 이 단계를 건너뛴다.

## 6단계: PR 생성
/pr 커맨드를 사용하여 커밋, 푸시, PR 생성을 수행한다.
PR 본문에 plan 문서 경로를 포함할 것.

## 주의사항
- plan 문서가 존재하지 않으면 작업 중단하고 안내
- 구현 중 컴파일 에러 발생 시 수정 후 재시도
- 전체 테스트 통과 확인 후 커밋
- 각 단계 완료 후 다음 단계로 넘어갈 것 (병렬 실행 금지)
